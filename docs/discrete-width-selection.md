# Дискретный отбор размеров по пользовательским порогам

Статус: [Windows run 42195265326 — SUCCESS](https://github.com/posmis/weld-engineering/actions/runs/42195265326), source `8f7d2e3`: 115 Rust/API, 117 frontend ×3, установленный EXE/one Undo/Redo/SQLite/restart, HTTP/OpenAPI, независимый разбор sizing/incomplete/applied PDF, NSIS/uninstall. UI-переработка остаётся в конце, тёмная тема по умолчанию. Это отбор среди явно заданного конечного списка коэффициентов, **не нормативная оптимизация, глобальный оптимум или подтверждение прочности**.

Прежний `POST /api/v1/studies/width` / Tauri `evaluate_width_study` получил optional `objective`: `minimum_volume` или `minimum_mass`. Если поле отсутствует/null, отбор отключён и прежнее ручное сравнение работает без пользовательских пределов. При явной цели Project.user_limits обязателен; нет пределов — ошибка `width_study_limits_required`, никаких автоматически назначенных значений.

Для каждого кандидата прежний Rust-модуль заново масштабирует эффективную ширину и оба исходных катета, пересчитывает все случаи и independent-nominal-components-v1. Дополнительно вызывается `prismatic-right-triangle-quantities-v1` на геометрии кандидата с прежним контекстом материалов. Row содержит optional/nullable `quantities` (с собственным source echo) и `quantity_error`. Номинальные статусы и ошибки оценки количества независимы: возможен complete analysis и явная ошибка объёма/массы. Ручное применение полностью рассчитанного номинального варианта сохраняется; ошибка количества или пользовательское превышение не выдаёт такой вариант за пригодный.

Критерий отбора:

1. Каждый случай номинально computed; механическая строка complete.
2. Контроль всех трёх пользовательских порогов полон и имеет статус within_user_limits. Взаимодействие компонент и применимость порогов по нормам не проверяются.
3. Все геометрические сечения заданы и целевая величина известна. Для массы дополнительно нужна применимая пользовательская плотность наплавленного металла. Partial known_volume не является полным объёмом; missing density не становится нулём.
4. Среди подходящих строк выбирается минимальная положительная конечная целевая величина. При точном равенстве — первая строка исходного списка. Функция не генерирует новых коэффициентов и не ищет непрерывное решение.

Ответ optional/nullable `selection`: objective, status complete/incomplete, eligible_count, unavailable_count, nullable selected_row_index (нулевая индексация) и objective_value (mm³ или kg), список exclusions `{row_index,reason}`. Приоритет причин: calculation_unavailable → limits_unavailable/limits_exceeded → quantity_error/quantity_unavailable. Известное превышение порога исключает строку независимо от её объёма/массы, не считается неизвестной пригодностью. Если хотя бы одна иная строка неизвестна, status=incomplete и минимум не выдаётся, даже если есть другие известные подходящие строки. Если все строки оценены и ни одна не подходит — status=complete, eligible_count=0, selected_row_index/objective_value=null. Это отсутствие варианта в заданном списке под пользовательскими порогами, не общий запрет конструкции по нормам.

Все расчёты, сравнение и отбор выполняет Rust; frontend проверяет согласованность полученного снимка. В окне «Размеры» есть цель отбора (по умолчанию «Без отбора»), объём/масса каждой строки и причины исключения. Изменение цели/коэффициентов/исходного проекта обесценивает прежний результат; поздние ответы не принимаются. Рекомендация не выбирает radio и не меняет Project. Кнопка «Выбрать минимум из таблицы» только отмечает строку; затем пользователь отдельно применяет размер. Применение повторяет прежний свежий расчёт и поддерживает один Undo/Redo, SQLite/restart. Новый Project/schema/migration не вводится.

Study PDF до применения содержит исходный weld-project.json, полный width-study.json с целью/таблицей/quantity sources/причинами/selection, прежний user-limit-comparison.json и исходный weld-quantities.json. Данные количества кандидатов относятся к их геометрии; самостоятельное исходное quantity вложение — к исходной геометрии. После применения обычный PDF показывает выбранную модель, а временная таблица в Project не сохраняется.

Для единого масштабирования f при фиксированных осях и нагрузках номинальная эффективная площадь ∝f, напряжения ∝1/f, треугольный объём и масса при постоянной плотности ∝f². Металл, исходные нагрузки/P/m/g/a и frozen sources сочетаний не изменяются. Нет стоимости, технологических/геометрических ограничений производства, зазоров/доступа, провара/усталости/расходных припусков, нормативных допускаемых напряжений и автоматической инерционной нагрузки от найденной массы. Консервативный численный отказ QuantityResult блокирует обе целевые величины, даже если одна могла бы быть представима отдельно. Бюджет по-прежнему ≤16 кандидатов и ≤32768 «кандидат×случай×участок».

Пройденные Windows-проверки: известные 3/4/100 и density 8000, факторы 2/1/0.5 с исключением превышения; неизвестные сечения/density/failed/quantity numerical range, missing criteria, отсутствие подходящих; RPC/HTTP/OpenAPI, frontend default/manual/смена цели/stale/PDF; установленный EXE с 3 случаями, [2,0.5,1.5,1e308] → incomplete, удаление failed → минимум 1.5 по массе, явное применение/one Undo/Redo/SQLite/restart; независимый PDF parser для объёма 10800 mm³/массы 0.0864 kg и уменьшения всех номинальных полей в 1.5 раза. Прочность остаётся unsupported, независимая инженерная валидация не заявлена; оригиналы публикаций не публикуются.
