# Пользовательские ограничения размеров

Статус: [Windows run 42197942523 — SUCCESS](https://github.com/posmis/weld-engineering/actions/runs/42197942523), source `f3deba2`: 121 Rust/API, 120 frontend ×3, установленный EXE/one Undo/Redo/SQLite/restart, HTTP/OpenAPI, независимый study/applied PDF, NSIS/uninstall. Тёмная тема по умолчанию сохранена, переработка UI в конце. Это заданные пользователем диапазоны, не нормативные/технологические ограничения ГОСТ, проверка пригодности или независимая инженерная валидация.

`WidthStudyRequest` и `ApplyWidthScaleRequest` получили optional `constraints`, по умолчанию пустой список. Не более трёх различных dimension: effective_width, leg_1, leg_2. Каждое правило содержит конечные положительные minimum_mm/maximum_mm с min≤max и source (1–500 символов, не пустой/пробельный). Оба конца диапазона включены; одинаковые нижняя/верхняя границы разрешены. Дубли величин, отрицательные/нулевые/NaN/Infinity границы, инвертированный диапазон и отсутствие источника отклоняются без подстановки defaults.

Правило применяется к каждому участку геометрии кандидата после масштабирования и канонического вывода a из модели сечения. Ширина — эффективная ширина номинального линейного сечения, не размер усиления. Катеты читаются только из явно заданного idealized_right_angle_fillet. Для вручную заданной ширины катеты неизвестны: никакого обратного назначения k=a*sqrt(2) или предположения равных катетов нет. Нагрузки, материалы, их контекст толщины/температуры и frozen sources не меняются.

Проверка own Rust `size_limits` возвращает SizeCheck с общим статусом и per-constraint/per-segment фактическими величинами, nullable при отсутствии модели, source и статусами within_limits/exceeds_limits/unknown. Известное нарушение имеет приоритет над unknown в сводном статусе; исходные unknown-строки остаются в деталях. Сравнения границ точные для конечных бинарных значений, без скрытого допуска/округления, которое расширяло бы диапазон. Возле границы возможен консервативный отказ из-за представления f64; вывод числа на экране не меняет результат сравнения.

WidthStudyResult содержит root constraints echo и optional row.size_checks. Механическая полнота и соблюдение диапазонов независимы: computed/complete не означают, что размеры в пределах. Ручное сравнение без objective тоже проверяет введённые диапазоны. Если список пуст — старое поведение, size_checks=null. Номинальные ошибки остаются failed/incomplete; если кандидат целиком не рассчитан, size_checks может быть null и применение заблокировано прежним правилом полноты.

Дискретный отбор учитывает правила после номинальной полноты/пользовательских порогов и перед известностью целевой величины. size_limits_exceeded — известное исключение, не неизвестная пригодность; size_limits_unknown увеличивает unavailable_count и блокирует выдачу минимума. Прочие ограничения отбора неизменны. Значения правил не назначаются по стандартам автоматически.

В окне «Размеры» раскрывается «Ограничения размеров», каждое правило добавляется явно, min/max/source изначально пустые. Пока правило некорректно, запуск недоступен. Цель/коэффициент/правило/источник меняются — прежняя таблица и выбор становятся неактуальными. Нарушенный/неизвестный размер блокирует radio и применение. Apply отправляет тот же список и заново проверяет его в Rust после свежего расчёта; endpoint не принимает нарушение даже при прямом вызове в обход UI (`width_study_size_limits_not_met`). Пользовательские пороги напряжений по-прежнему не становятся нормативной оценкой прочности.

Правила — часть временного исследования, как список коэффициентов и цель. Перед применением/закрытием их сохраняют в study PDF: исходный Project, полный width-study.json с constraints, фактическими величинами, источниками и причинами исключения; читаемый текст включает все участки. В Project/SQLite сохраняются выбранная геометрия и расчёты, правила и таблица в Project не добавляются. Версия Project/миграция не меняется; старые запросы работают без constraints. Для нового исследования правила задаются заново.

Пример: исходные оба a=7.2 mm, катеты 9/12, V=10800 mm³, m=0.0864 kg. Коэффициенты [0.75,1.25,1.5], диапазон a∈[8,10] mm: [5.4,9,10.8] mm. Все пользовательские пороги напряжений могут быть соблюдены, но остаётся только средний кандидат: a=9, катеты 11.25/15, V=16875 mm³, m=0.135 kg. Выбор и применение явные, один Undo/Redo, SQLite/restart. Ни один из этих размеров не заявлен нормативно допустимым или технологически выполнимым.

Пройденные Windows-проверки: включённые границы всех трёх величин, неизвестные катеты/известное нарушение+unknown, неверные/дубли/источники, fresh study/apply/unknown-apply rejection; HTTP/OpenAPI и прямой запрет нарушения, frontend blank/source/echo/blocked radio/forwarded apply; установленный EXE с 3 случаями, lower/upper exclusion и factor1.25, Undo/Redo/SQLite/restart; независимый pypdf для правил, всех actual values, объёма/массы, неизменных нагрузок и полей ÷1.25. Публикации не публикуются.
