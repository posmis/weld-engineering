# Итерация 01 — Windows desktop и application service

## Реализованный scope

- Tauri 2/React/TypeScript Windows-клиент: русские/английские ресурсы, две темы, числовое редактирование участков и нагрузки, SVG-схема из входных данных, реальные вызовы Rust.
- Независимый weld-application с versioned Serde contracts, ограничениями входа, структурированными ошибками и раздельными статусами математики/прочности/валидации.
- Перенос силы/момента к вычисленному центру сечения. Номинальное F/A только при точно нулевой результирующей паре. Ненулевые моменты не отбрасываются по допуску.
- Точная рациональная проверка перекрытий/пересечений для конечных входных координат; общие конечные точки разрешены.
- SQLite migrations и неизменяемые ревизии, открытие исходного результата без пересчёта, JSON импорт/экспорт с ограничением 1 МиБ и проверкой согласованности snapshots.
- Защита от исчезновения площади при underflow; регрессионные и аналитические тесты геометрии/нагрузок.
- Cargo.lock, package-lock.json, закреплённый Rust 1.99.1, Windows pipeline и оригинальная иконка приложения с генератором.

## Нативный smoke test

scripts/windows-desktop-smoke.ps1 предназначен для запуска готового Windows EXE в интерактивной Windows-сессии. Он использует UI Automation: нажать «Рассчитать», дождаться реального результата Rust в WebView, сохранить ревизию, создать новый проект и снова открыть сохранённый снимок. Backend не подменяется. Сценарий фактически прошёл на Windows в прогоне 41836367640: в журнале зафиксирован PASS полного пути native window → WebView → Rust calculation → SQLite save → snapshot reopen. Backend и результат в этом сценарии не подменялись. Это не проверка всех функций и не независимая инженерная валидация прочности.

## Ограничения и следующие шаги

Нет нормативного метода прочности, допускаемых напряжений, pass/fail, свойств материалов, автоматического подбора, стандартных сечений, PDF и REST. Нет перетаскивания концов и изображения геометрии стандартного соединения. Модель F/A явно номинальная; не является независимой инженерной сертификацией.

Следующие шаги: добавить защиту несохранённых изменений; расширить геометрию и редактор; завершить проверку прав/источников нормативной методики и только после этого реализовывать сопротивления/подбор. Полные ГОСТы, книги и OCR-тексты не входят в Git/CI artifacts. Артефакт pipeline содержит только собственный EXE приложения; target cache не содержит локальной библиотеки публикаций.
