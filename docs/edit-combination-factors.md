# Редактирование коэффициентов сохранённого сочетания

Статус: [Windows run 42121612434 — SUCCESS](https://github.com/posmis/weld-engineering/actions/runs/42121612434), исходники `e3a0d094528f66962e9669c153e293f6de028e22`. Основа — [пользовательское сочетание](user-load-combinations.md), метод `user-linear-load-combination-v1`. Это пользовательская линейная суперпозиция, не назначение нормативных коэффициентов. Переработка UI остаётся завершающим этапом.

## Поведение

В свойствах активного сочетания нажать «Коэффициенты сочетания». Диалог восстанавливает название, исходные случаи и сохранённые коэффициенты. «Применить коэффициенты» заменяет существующий случай: его ID, позиция и общее число случаев сохраняются. Нагрузки выводятся заново по сохранённым источникам, результат только этого случая сбрасывается. Другие случаи и их результаты не меняются. Один Undo/Redo возвращает весь снимок; SQLite сохраняет новую ревизию, прежняя не изменяется.

Используются замороженные нагрузки, имена и порядок источников. Изменение или удаление живых исходных случаев не подменяет снимки. Источники массы сохраняют m/g/a/P; отрицательный коэффициент масштабирует силу, не создаёт отрицательную физическую массу. Порядок терминов API может отличаться: порядок источников/сил и их id остаётся прежним. Ноль исключает вклад, но не удаляет источник из аудита. Для другого набора исходных нагрузок создать новое сочетание.

При 32 существующих случаях редактирование разрешено; добавление 33-го по-прежнему запрещено. Ограничения на конечность коэффициентов, хотя бы один ненулевой коэффициент, число сил, численный диапазон и размер документа остаются прежними. Нельзя этим режимом заменить обычный случай; цель должна иметь корректную модель сочетания. Неизвестный/повторный/пропущенный источник отклоняется.

## Контракт

`CombinationRequest` получил optional `replace_case_id`. При отсутствии поля прежний путь создаёт новый случай из живых обычных случаев. При наличии — обновляет существующее сочетание по его `combination.sources`; `terms` обязаны содержать каждый сохранённый source.case_id ровно один раз. Поля title/factor редактируемы, поля load/имя/id источника не берутся из внешних живых случаев.

Тот же Tauri `create_load_combination` / POST `/api/v1/cases/combine` возвращает Project с активной целью. Даже если до вызова активен другой случай, обновляется/активируется именно replace_case_id. Старые запросы без поля продолжают создавать сочетания. Структура проекта и метод вывода не меняются; OpenAPI описывает новую опцию. Frontend отклоняет edit-ответ с изменившимся ID или числом случаев; поздний ответ после изменения/закрытия проекта не применяется.

## Собственные эталоны и Windows-проверка

Из исходных A/B в предыдущем модуле для 3A−2B: FΣ=(−60,−10,−300) N; MΣ,C=(−5772,1256,1384) N·mm. Тест удаляет живые A/B перед обновлением и сохраняет источник массы/точки в снимках. Другой эталон: A=600 N/B=−200 N, после создания изменить живую A на 999 N. Обновление коэффициентов на 1/−1 обязано дать 800 N, σz=4 MPa при Aсеч=200 mm², используя замороженные 600 N, а не 999 N.

Windows Rust/API проверки: сохранённые источники/порядок/ID, переключение активной цели, неизменность других результатов, старая/новая SQLite-ревизии и JSON, ошибочные цели/термины, лимит 32, настоящий HTTP/Test-Json. Frontend: восстановление коэффициентов удалённых источников, request replace_case_id, отказ изменённого ID/числа случаев, применение и два независимых Undo в App.

Пройденный native сценарий изменяет 1,25/−0,5 на 2/−0,25: остаются 3 случая; силы Fz=1200/25/−75 N и FΣ=(5,0,1150) N. Проверяются Undo/Redo, расчёт 3/3, SQLite/restart, повторное открытие коэффициентов и отдельный PDF. Независимый pypdf сравнивает старый и новый отчёты: одинаковые ID/исходные нагрузки/остальные случаи, новые коэффициенты и фактический snapshot результата. В Windows прошли 90 Rust/API-тестов и 95 frontend-тестов ×3, fmt/Clippy, TypeScript/Vite/dev/release, настоящий HTTP/OpenAPI/C#, установленный EXE/NSIS/uninstall и независимый PDF parser. strength_status остаётся unsupported_calculation. Linux builds/tests не выполняются; ГОСТы/книги не публикуются.
