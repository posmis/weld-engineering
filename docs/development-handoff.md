## Что уже существует
- Cargo workspace с одним crate weld-core, без внешних зависимостей.
- Типы физических единиц, проверки конечности и положительности геометрических размеров.
- Интегралы прямолинейных плоских элементов постоянной эффективной ширины: длина, площадь, центр, Ix/Iy/Ixy/J.
- Перенос силы/момента: M_O=M+(P−O)×F.
- centred_direct_traction: три подписанных номинальных компонента F/A для центральной нагрузки без моментов. Ширина эффективного сечения задаётся явно, не выводится из катета/провара.
- assess_strength: всегда UnsupportedMethod. Нет реализованной проверки прочности, запаса, допуска, оптимизации или соответствия ГОСТ.
- Семь подготовленных Rust-тестов и GitHub Actions для Windows. На момент подготовки документа ни локальный Windows-прогон, ни результат Actions не получены.
- JSON реестры содержат статусы/происхождение источников, а не готовые проверенные нормативные таблицы.

## Жёсткие ограничения
- ГОСТы, книги, сканы и полные извлечённые тексты НИКОГДА не отправлять в GitHub, PR, CI artifacts, отчёты или сторонние сервисы. Запрет распространяется на смену расширения и OCR-копии. Хранить только в среде вне checkout.
- Разрешено сохранять собственные инженерные выводы, короткие описания результатов исследования, библиографию, URL и контрольные хеши. Не перепечатывать целые нормативные таблицы в Git под видом документации или dataset. Перед импортом нормативных данных отдельно проверить права и согласовать допустимый способ поставки, например локальный импорт пользователем.
- Разработка и начальные испытания — Windows 10/11 x64. Текущая облачная машина Linux; не устанавливать здесь Linux Tauri и не заявлять Windows-готовность по Linux-сборке. CI использует windows-2022.
- Русский UI по умолчанию, английский через translation files. Вычисления Rust, не JavaScript.
- Не применять строительные нормы к машинным деталям автоматически. Сначала проверить применимость конкретного правила и источника.
- Не публиковать среду автоматически. Push кода и публикация cloud environment — разные операции.
- Существующий checkout уже изолирован; worktree создавать только по прямому запросу пользователя.

## Ближайшая последовательность работ
1. Проверить фактический результат Windows Actions после первого push. Если workflow не запускается, установить причину, не считать наличие YAML прохождением проверок. Исправить fmt/clippy/численные дефекты. Зафиксировать версию Rust и lockfile после успешного Windows-прогона.
2. Добавить тесты геометрии на поворот, смену координат, крайние масштабы, переполнение/потерю точности, отрицательные/нулевые ширины и пересечения. Задать проверяемую численную политику вместо произвольных констант. Не допускать двойного счёта площади при наложении сегментов.
3. Оформить application service с versioned Serde input/output, явными единицами, ошибками и validity. Математический результат хранить отдельно от strength acceptance. Tauri commands только адаптер.
4. Реализовать versioned project snapshots и SQLite migrations; проверять ограничения входа и открытие неизвестной schema_version. Исторический результат не пересчитывать при открытии.
5. Реализовать минимальный рабочий Tauri 2/React клиент: числовое редактирование сегментов/нагрузки, диаграмма из входной модели, вызов Rust, реальные результаты и понятный статус unsupported strength. Это промежуточная функциональность, не прочностной MVP.
6. Параллельно завершать нормативный этап, описанный ниже. После проверки конкретного метода реализовать прочность, независимые эталоны, GUI и отчёт для его ограниченной области. Только затем автоматический подбор.
7. Закрывать последующие фазы по матрице scope-and-acceptance.md. Не реализовывать невалидированные усталость/давление/лазерную прочность как заглушки с успешным статусом.

## Незавершённое исследование
- Действующий статус ГОСТ 5264-80, 14771-76, EN 1011-6-2025 подтверждён официальным каталогом nd.gostinfo.ru на дату исследования. Это не бессрочное разрешение; перед новыми нормативными расчётами нужна проверка актуальности.
- ГОСТ EN 1011-6-2017 — заменён, только исторический аудит.
- Поправка 2025: официальные реквизиты ИУС 6-2026, ввод 17.06.2026. Вторичная публикация Меганорма добавляет Таджикистан в таблицу согласования; полный официальный лист ещё не сверялся.
- Не установлены точные национальные принятия остальных частей EN 1011. Простой поиск каталога игнорирует значимые дефисы; отсутствие точного результата не доказывает отсутствие стандарта.
- FKM Analytical Strength Assessment for Machine Components, 7th edition 2020, ISBN 978-3-8163-0745-7: кандидат для машинных деталей. Подтверждены описание/оглавление издателя, полного текста нет. Не покупать и не принимать платные условия без отдельного разрешения. Не восстанавливать формулы/коэффициенты по оглавлению.
- NPTEL — открытый учебный источник для независимых механических выводов, не национальная нормативная методика. В лекции 25 выявлены противоречивые записи; они не импортированы.
- Пособия ОГУ/АлтГТУ и RoyMech содержат строительные основания; их коэффициенты и сопротивления исключены для автоматического переноса.
