# Будущий Autodesk Inventor adapter

Add-in сейчас не реализуется. Отдельный C# adapter извлекает геометрию из Inventor API, переводит единицы документа в явно указанные mm/N/N·mm, преобразует оси в правостороннюю систему запроса и передаёт данные локальному versioned API. Для точек учитывать и поворот, и перенос; для сил только поворот; для моментов дополнительно учитывать перенос точки приложения через r×F.

Не считать линии модели эффективными сечениями без подтверждения инженером и выбранным методом. Сохранять ID деталей/рёбер и преобразование CAD↔расчётная система для возврата критических точек. Возвращать исходные единицы/оси, статус применимости и снимок версии метода. Перед записью атрибутов проверять ревизию документа. Несовместимая версия API и неподдерживаемая пространственная группа должны отклоняться явно. Inventor не нужен для автономного ядра и не установлен/не тестировался.

## Действующий транспорт

Локальный API теперь реализован: [api-reference.md](api-reference.md), [OpenAPI](openapi.json). Пример [Program.cs](../examples/inventor-client/Program.cs) — самостоятельный .NET 8 Windows console client, без Inventor interop. Запустите start-api.bat, затем `dotnet run --project examples/inventor-client`. CI компилирует пример на Windows; настоящий Inventor add-in по исходному требованию не создаётся.

### Единицы, система и перенос результатов

1. Получить единицы через UnitsOfMeasure документа; не считать численные значения Inventor уже миллиметрами. Внутренние единицы длины Inventor обычно cm: конвертируйте через API, а не фиксированный коэффициент без проверки. Силы/моменты берите из инженерных данных с явными единицами, они не следуют из геометрии рёбер.
2. Выбрать плоскость расчёта с ортонормальным правым базисом (ex,ey,ez) и началом O в единицах mm. Точка: q=Rᵀ(p−O), сила: f=RᵀF, свободный момент: m=RᵀM. Не добавлять r×F дважды: application.point_mm уже позволяет Rust перенести силу к центру. Передавать пару и точку относительно одного O. Отражённый/левый базис запрещён; нормализовать масштаб отдельно от поворота.
3. Отклонить непрямолинейные и неплоские швы. Текущий DTO хранит только прямые XY-участки; проекция пространственного/кривого шва в 2D изменяет задачу и не должна происходить молча. Разбиение кривой требует отдельно проверенной методики сходимости, её пока нет.
4. Пользователь подтверждает effective_width_mm каждого участка; длина ребра, катет, тип по ГОСТ и эффективная ширина не взаимозаменяемы. Общие концы допустимы, пересечения/T-стыки/наложения отклоняются текущим exact geometry validator.
5. Перед запросом сохранить версию CAD-документа, стабильные reference keys рёбер, O/R и соответствие index→edge. При приходе ответа сравнить ревизию: изменившийся документ делает ответ устаревшим. HTTP cancellation не считается отменой уже начавшегося Rust-расчёта.
6. Для вывода точки обратно использовать p=O+Rq; вектор компонент напряжений преобразовывать с учётом их определения (traction на выбранной нормали), не объявлять компоненту σz готовым локальным throat stress. Отображать unsupported_loading, неполноту batch и ошибки каждого случая. Никогда не создавать зелёный «прочность обеспечена» из computed.
7. Сохранить вместе с CAD reference keys, исходный запрос и ответ, engine_version/method_id/schema, статусы и предупреждения. Проверка snapshots в API подтверждает согласованность структуры, не подлинность внешних результатов.

API v1 не пишет в модель/файлы CAD. Запись свойств будущим add-in требует явного пользовательского действия и проверки ревизии; нормативная пригодность остаётся отдельной, пока неподдерживаемой задачей.
