# Контроль пользовательских пределов номинальных напряжений

Статус: реализовано в исходниках; Windows текущего SHA ожидается. Метод independent-nominal-components-v1 — собственный арифметический контроль трёх независимых порогов, **не нормативная оценка прочности сварного соединения**. Нет взаимодействия напряжений, локального горла, концентраций, пластичности, усталости, давления или назначения допускаемых значений. UI-переработка остаётся завершающим этапом.

## Определение

В принятой номинальной модели поле t=(τx,τy,σz) относится к общей плоскости XY с нормалью Z. Пользователь явно задаёт три конечных положительных порога в MPa с отдельными источниками:

- tension: окончательный положительный порог растяжения;
- compression: положительный модуль порога сжатия;
- shear: порог длины вектора (τx,τy).

Материалы/Rp0.2/Rm и коэффициенты не подставляются. Источник — ссылка/пункт/пользовательский протокол до 500 символов, без полных текстов публикаций. Нельзя объявить данные verified/GOST-pass выбором метода или скрытого поля: DTO строгий, метод фиксирован. Нет автоматического применения safety factors: значения считаются окончательными пользовательскими порогами.

D_t=max(0,max σz), D_c=max(0,−min σz), D_s=max hypot(τx,τy). Отношения u_t=D_t/T, u_c=D_c/C, u_s=D_s/S; наибольшее отношение определяет случай/компоненту/участок/конец. Ровно u=1 входит в пользовательский порог; любое u>1 — превышение этого порога. Допуск сравнения не добавляется. Округление на экране/PDF не изменяет решение; исходные числа сохраняются во вложенном JSON.

Для uniform-direct-traction-v1 берётся сохранённый F/A; для аффинного elastic-line-traction-v1 — значения обоих концов каждого участка. Нормальная компонента аффинна, её экстремумы — в концах; норма аффинного вектора среза выпукла, максимум тоже в конце. Нулевой спрос имеет u=0 и point=null; ненулевой — точный индекс участка/конец. Равные экстремумы выбираются детерминированно: порядок случаев, затем участков/start/end и компонент tension/compression/shear.

Переполнение отношения или исчезновение ненулевого отношения в ноль/субнормальный диапазон → numerical_range. Неконечные/неположительные пороги и пустые источники → invalid_user_limits. Значение unknown не заменяется нулём. Сравнение использует существующие сохранённые номинальные результаты: оно не пересчитывает историческую механику и не удостоверяет подлинность импортированного снимка. Для свежего расчёта сначала выполнить «Рассчитать»/«Рассчитать все».

## Статусы и полнота

По случаю: within_user_limits, exceeds_user_limits или unavailable (reason=not_computed/unsupported_loading). Недоступный случай имеет null вместо трёх проверок. Никакой отсутствующий/неподдерживаемый случай не исчезает из total.

Общая сводка incomplete, если available<total, даже когда все доступные случаи внутри порогов. Сохраняются число известных превышений и максимум только доступных отношений; это не полный результат. Если все доступны, сводка exceeds_user_limits при любом превышении, иначе within_user_limits. Ноль доступных случаев даёт maximum_ratio/governing=null. strength_status всегда unsupported_calculation, validation_status — not_independently_validated. В интерфейсе нет зелёного нормативного pass. «В пределах пользовательских значений» не означает, что соединение выдерживает нагрузку по стандарту или сочетанию критериев.

## Контракт и работа

Optional Project.user_limits={method_id,tension,compression,shear}, каждый порог — {value_mpa,source}. Старые JSON без поля читаются/сериализуются без него; SQLite/схема проекта не мигрируют. Старому строгому reader для нового поля нужно обновление.

- Tauri validate_user_limits / POST `/api/v1/limits/validate`: {schema_version:1,limits} → UserLimits. Можно настроить пороги при незавершённой геометрии; нельзя превращать NaN черновиков в JSON-null/ноль.
- Tauri evaluate_user_limits / POST `/api/v1/limits/evaluate`: {schema_version:1,project} → LimitEvaluation с критериями, случаями, source method id, demand/limit/ratio/point, полной сводкой и независимыми статусами прочности/валидации. project.validate проверяет связность снимков, не пересчитывает их.

«Пределы» на панели инструментов открывает ввод без значений по умолчанию. После явного ввода и Rust-валидации назначение — одно действие Undo/Redo; его можно удалить. Данные сохраняются в JSON/SQLite/PDF. Изменение порогов сохраняет механику всех случаев и заново сравнивает её с новым набором порогов. Изменение нагрузки/геометрии инвалидирует механику прежним способом; сводка становится неполной до нового расчёта. Старый асинхронный ответ не показывается для изменившегося проекта/критериев. Пока в нагрузках есть неконечный черновик, он не отправляется в API сравнения; отображается неполнота.

PDF печатает явные пределы/источники, метод, статусы, полноту, отношения и определяющие точки. Применённое сравнение приходит из Rust; ответ с другими критериями отклоняется. Вложения: weld-project.json с исходными данными и механическими снимками, user-limit-comparison.json с неокруглёнными demands/ratios и статусами, лицензия шрифта. Без ответа сравнение не придумывается.

## Собственные эталоны и подготовленная проверка

1. A=200 mm², F=(800,600,600) N → (τx,τy,σz)=(4,3,3) MPa; векторный срез=5 MPa. Пороги T=3/C=4/S=5 дают отношения 1/0/1, равенство разрешено только в смысле этих пользовательских порогов. Fz=−1000 N → D_c=5 MPa, u_c=1,25, превышение.
2. Две линии x=−50…50, y=±20, a=2 mm; Fz=600 N, Mx=160000 N·mm → σz от −18,5 до +21,5 MPa. T=C=20 MPa → u_t=1,075, u_c=0,925; определяет S2/start. Это номинальная арифметика, не реальный коэффициент запаса.
3. Центральные 1800 N при A=200 mm² дают 9 MPa. T=6 MPa → отношение 1,5. Один отсутствующий случай сохраняет total=3, available=2 и incomplete; известное превышение остаётся показано.

Подготовлены Windows Rust/API/frontend проверки: знаки/векторный срез/границы/точки/неполнота, неверные/фиктивные данные, численные отказы, JSON/SQLite/старые ревизии, незаполненные нагрузки/поздние ответы, независимое сохранение/удаление/Undo, настоящий HTTP/OpenAPI/Test-Json. Native: пороги 10/20/5 → превышения; правка активной силы → неполнота 2/3; Undo восстанавливает 3/3; новые пороги 10^6 MPa дают «в пределах пользовательских значений», сохраняя unsupported strength; SQLite/restart/PDF. Независимый pypdf сверяет demand/ratio по исходным signed normal/vector shear полям и полную неизменность механики/материалов. Проверки не считаются пройденными до фактического Windows run. Linux builds/tests не выполняются; ГОСТы/книги не публикуются.
