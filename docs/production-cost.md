# Пользовательская оценка времени и стоимости

Статус: реализация, Windows-проверки ожидаются. Оценка `user-travel-time-cost-v1` — один явно заданный производственный сценарий для всей группы. Не WPS/WPQR, нормативный подбор процесса, проверенный прайс, фактический расход или бухгалтерский расчёт. UI-переработка в конце; тёмная тема по умолчанию.

Пользователь задаёт process_label, currency_label (без конвертации), source и все численные параметры: скорость mm/min >0, число проходов каждого участка (целое u32 >0), долю горения дуги внутри сварочной операции (0,1], подготовку/операторский контроль min ≥0, ставки труда/оборудования в валюте за час ≥0, цену присадки в валюте/kg ≥0, коэффициент использования присадки (0,1] и стоимость внешнего контроля ≥0. Пустые значения не становятся нулями или типовыми коэффициентами. Нулевые ставки допускаются только как явный пользовательский ввод с источником. Сценарий имеет один источник (до 500 символов), описание процесса (100), обозначение валюты (12); курс/ISO-код и достоверность цен не проверяются.

Собственный размерный вывод:

- L — сумма длин осей всех участков, mm. Каждый участок проходит заданное число n раз с одной скоростью v.
- Время дуги ta=L*n/v, min.
- Сварочная операция tw=ta/f, где f — доля дуги. f учитывает только внутрисварочные паузы/переходы; подготовка и контроль не включены в f.
- Полное время T=t_prepare+tw+t_inspect. Труд C_labor=T/60*rate_labor; оборудование C_equipment=tw/60*rate_equipment. Для подготовки/контроля оборудование этой моделью не тарифицируется.
- Геометрическая масса швов m берётся из `prismatic-right-triangle-quantities-v1` с применимой пользовательской плотностью наплавленного металла. Потребность присадки mc=m/eta; материалы C_material=mc*price_kg.
- Внешний контроль — отдельная услуга, без уже учтённого труда оператора. Известная часть без материалов S=C_labor+C_equipment+C_external. Полная оценка C=S+C_material, в одной валюте без округления до денежной минимальной единицы.

Число нагрузочных случаев не множитель производства: группа изготавливается один раз, даже если рассчитаны 32 случая. Модель не выводит число проходов/скорость/долю дуги по геометрии или процессу. Нет проверенных режимов/качества, газа, энергии/налогов/накладных/прибыли/амортизации отдельными моделями; состав заданной ставки оборудования определяет пользователь. Геометрическая масса исключает провар/усиление/объединение пересечений/припуски; eta не заменяет проверки реального расхода.

Если нет полной модели сечений или применимой weld-density, consumed_mass/material_cost/total_cost=null, complete=false, даже при явно нулевой цене присадки. Известное время и subtotal показываются отдельно, не выдаются за полную дешёвую стоимость. Переполнение, subnormal положительные промежуточные величины и потеря ненулевого результата возвращают numerical_range, не ноль; промежуточная арифметика консервативна даже при потенциально представимом конечном произведении.

Optional `Project.production_parameters` сохраняется прежним JSON/SQLite; старые проекты без поля читаются, schema_version/физическая миграция не меняются. Валидация параметров не зависит от исправности геометрического черновика. Добавление/изменение/удаление сценария — одно Undo, номинальные input/все snapshots сохраняются. Изменение геометрии/материалов/сценария обесценивает прежнюю оценку; поздний ответ игнорируется. Масса/стоимость не создаёт нагрузку автоматически и не влияет на номинальные напряжения/прочность.

Tauri `validate_production_parameters`, `evaluate_production_cost`. REST `POST /api/v1/production/validate` с `{schema_version:1,parameters}` → ProductionParameters и `/api/v1/production/evaluate` с `{schema_version:1,segments,materials,parameters}` → ProductionResult. Строгие DTO, source echo, QuantityResult, времена/компоненты/complete/nullable total. Прежние loopback/auth/workers/body/deadline ограничения. В UI — раздел «Производство и стоимость» панели результатов, кнопка параметров; новые поля пустые, сценарий задаётся явно.

В сравнении размеров новая objective=minimum_cost требует Project.production_parameters и всех явных пользовательских порогов. Для каждого кандидата стоимость заново вычисляется на его геометрии и прежнем сценарии; пользовательские размерные ограничения и пороги нельзя обменивать на дешевизну. Неполная производственная оценка/ошибка исключает неизвестного кандидата и блокирует минимум. Явные нулевые ставки могут дать нулевую известную стоимость; при точном равенстве — первая строка. Процессы/скорости/прайсы/валюты между строками автоматически не оптимизируются. Результат — минимум среди заданных коэффициентов, не глобальный или нормативный оптимум. Применение ручное, параметры сохраняются.

PDF содержит формулы/допущения, все параметры/источник/валюту, компоненты и unknown; `production-cost.json` с точным source и результатами. Снимок с другой геометрией/материалами/сценарием не подставляется. Study PDF дополнительно хранит candidate production_cost/production_error в width-study.json и исходную оценку отдельно. При отсутствии свежего результата параметры печатаются с «не рассчитано», без выдуманной суммы.

Эталон: две оси по 100 mm, катеты 11.25/15, a=9, m=0.135 kg; v=100, n=2, f=0.5, подготовка10/контроль5 min, труд600/оборудование300 за час, цена200/kg, eta=0.9, внешняя услуга50 RUB. ta=4, tw=8, T=23 min; труд230, оборудование40, материал30, внешний50 → 350 RUB. Неизвестная плотность: известная часть320, полная стоимость неизвестна. При масштабировании катетов f_size=1.25 длины/заданные проходы прежние: материал46.875, полный C=366.875 RUB.

План Windows-проверки: арифметический эталон/unknown/явные нули/overflow/валидация; JSON/SQLite со старыми проектами и сохранными номинальными snapshots; обе REST команды/OpenAPI и cost objective с размерами; frontend пустые поля/late validation/stale result/метаданные one Undo/PDF provenance; установленный EXE 350/unknown/Undo/Redo/restart, constrained minimum_cost и ручное применение; независимый pypdf для четырёх новых собственных PDF и всех прежних сценариев. Нормативная прочность unsupported; публикации не публикуются.
