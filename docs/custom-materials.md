# Пользовательские материалы и проверка применимости свойств

Статус: [Windows run 42126360576 — SUCCESS](https://github.com/posmis/weld-engineering/actions/runs/42126360576), исходники `6fceea65b3009a33a714fe55ef1bc686a95de44e`. Это проектные пользовательские карточки, **не проверенная база материалов ГОСТ и не нормативная оценка прочности**. Переработка UI остаётся в самом конце; добавлен только ввод и просмотр данных нового модуля.

## Модель

В проекте optional materials={context,base,weld}. Контекст толщины mm/температуры °C задаётся явно, общий для двух карточек, не выводится из ширины a, катета или геометрии швов. Для разных физических условий основного/наплавленного металла требуется отдельная будущая модель назначений; текущий контекст — условия запроса к обеим карточкам. Карточки ролей независимы; null означает «не задана».

MaterialCard: kind=custom, designation, nullable product_form/condition, properties[]. Поддерживаются yield_strength (Rp0.2), tensile_strength (Rm), elastic_modulus (E) в MPa и density в kg/m3. Каждая запись содержит положительное конечное value, толщину (t_min,t_max], температуру [T_min,T_max] и непустой source (ссылка/пункт/протокол). Полные публикации в карточку не копируются. Источники — пользовательские сведения; даже ссылка на ГОСТ не превращает запись в verified. kind=verified_standard/verification_status=verified и другие неизвестные поля отклоняются строгим DTO.

Нет предзаполненных марок/прочностей/E/плотностей, нормативных минимумов, единиц в kgf или автоматической интерполяции. Температура ограничена снизу −273,15 °C; толщина запроса строго положительна. Для записей t_min>=0, t_max>t_min; T_min<=T_max. Совпадающие температурные границы включены с обеих сторон; совпадающие толщинные границы принадлежат только предыдущему диапазону. Неоднозначное пересечение доменов одного свойства в одной карточке → material_property_overlap. Пересечение разных видов свойств допустимо. До 32 записей на карточку; обозначение до 100 символов, форма до 100, состояние до 200, источник до 500. Действует общий предел проекта 1 MiB.

## Проверка применимости

Tauri evaluate_materials(request), POST `/api/v1/materials/evaluate`: MaterialRequest={schema_version:1,selection}; ответ MaterialEvaluation={schema_version,selection,base,weld}. Для каждой роли всегда возвращаются четыре вида свойства. В домене явной записи — value/source/status=user_provided. Вне диапазона, без карточки или без записи — value=null, source=null, status=unknown. Никаких нулей, ближайших записей, экстраполяции, значения по умолчанию или нормативного pass. Температурный промежуток между двумя записями остаётся неизвестным.

Собственные синтетические эталоны: Rp0.2=300 MPa на (0;10] mm и 280 MPa на (10;20] mm при [20;40] °C. При t=10/T=20 возвращается 300; t=10,00000001 — 280; t=20/T=40 — 280; t>20 или T>40 — unknown. Два диапазона толщины (0;10]/(10;20] не перекрываются. Два температурных [20;40]/[40;60] при одинаковой толщине перекрываются в T=40 и отвергаются. Все числа — искусственные тестовые данные, не свойства реальной марки.

## Проект и работа

Команда «Материалы проекта» открывает форму. Толщина/температура и новые значения по умолчанию не заполнены. Можно оставить обе роли неизвестными либо ввести designation и явные записи свойств. «Проверить применимость» вызывает Rust; только актуальный ответ включает «Применить материалы». Изменение контекста/карточки инвалидирует предыдущий ответ. Поздний ответ при изменении назначения/закрытии диалога не применяется. Cancel/нативное закрытие отменяют черновик.

Применение — одно действие истории: Undo/Redo восстанавливают карточки. SQLite хранит новые immutable ревизии и исходные записи/источники; JSON проекта включает материалы, старые данные без поля читаются как materials=None и сериализуются без него. SQLite/версия проекта не мигрируют. Старому строгому reader для поля materials нужно обновление.

Свойства **пока не используются** в номинальной механике. Изменение назначения/контекста сохраняет прежние входы и расчётные снимки всех случаев: текущие F/A, линейный изгиб и полярное кручение не зависят от этих карточек. Различие модулей E не включает неоднородный расчёт. Нет определения допускаемых напряжений, коэффициентов или критерия прочности. strength_status=unsupported_calculation, validation_status=not_independently_validated сохраняются. Будущий материалозависимый метод потребует новой связи со снимками и независимой инженерной валидации.

PDF печатает custom-статус, контекст, карточки, сырые значения с диапазонами/источниками и отдельно применимые/неизвестные свойства. Применимость для PDF приходит из Rust. При несовпадении ответа с проектом отчёт отклоняется; без ответа не придумывается применимость. Вложенный JSON содержит исходное назначение. Сырые 300 MPa в карточке за пределами домена не означают применимые 300 MPa в выводе.

## Проверка Windows

Windows Rust/API: границы/пробелы/пересечения/unknown, неверные размеры/температуры/источники/фиктивная верификация, JSON/SQLite/старые ревизии и неизменная номинальная механика. Frontend: пустой контекст, unknown без подстановки нуля, инвалидирование preview/поздний ответ, заполнение/сохранение/Undo/Redo и PDF. HTTP/OpenAPI/Test-Json: custom 300 MPa при t=10 и unknown при t=21, валидация проекта с карточкой.

Native: ввод синтетической карточки с 300 MPa на (0;20] mm/[20;20] °C, Rust, Undo/Redo, сохранение/restart. Затем контекст t=21, новый запрос возвращает unknown; все 3 механических случая остаются рассчитанными. Независимый pypdf читает карточку/источник/диапазоны в JSON, unknown в разделе основного металла и сравнивает все исходные нагрузки/результаты с предыдущим PDF. Все перечисленные проверки прошли: 95 Rust/API-тестов, 100 frontend-тестов в каждом из трёх свежих процессов, fmt/Clippy, TypeScript/Vite/dev/release, настоящий HTTP/OpenAPI/C#, установленный EXE/SQLite/restart/NSIS/uninstall и независимый pypdf. Linux build/tests не выполняются; ГОСТы/книги не публикуются.
