# Прослеживаемость и выпуск данных

Проект нормативной записи: standard_id, standard_designation, standard_title, edition, amendment, jurisdiction, effective_date, status, source_url, source_document_reference, clause, table, applicability, engineering_parameter, value, unit, verification_status. Отсутствующие сведения хранятся как unknown/NULL. registry.json пока содержит только очередь исследования, не нормативные записи.

Путь публикации: кандидат → подтверждение официального статуса → получение полного текста → перенос параметров → независимый обзор → тесты применимости и эталоны → выпуск неизменяемого dataset. Каждое изменение статуса/поправки инвалидирует связанные методы до ревалидации. При пересчёте повторно проверяется актуальность реестра; при недоступности проверки расчёт блокируется. Политика срока актуальности ещё требует согласования с нормативным экспертом, срок не выдумывается.

Исторические редакции доступны в архиве проекта, но не для новых расчётов. Не подменять сохранённый результат новым dataset. Автоматическое разрешение цепочки замен требует обнаружения циклов, неоднозначности, будущих дат вступления и разных юрисдикций; алгоритм пока не реализован.
