# Геометрический объём и масса швов

Статус: [Windows run 42191406499 — SUCCESS](https://github.com/posmis/weld-engineering/actions/runs/42191406499), source `b0edbc6`: 110 Rust/API, 114 frontend ×3, установленный EXE/SQLite/restart/Undo, HTTP/OpenAPI/C#, независимый разбор 10 PDF, NSIS/uninstall. Собственный метод `prismatic-right-triangle-quantities-v1` оценивает идеализированные призмы. Это не нормативная прочность, фактический расход присадки или закупочная масса. UI-переработка остаётся последним этапом; тёмная тема по умолчанию сохранена.

Для участка с явно заданной моделью `idealized_right_angle_fillet` площадь треугольника B=k1*k2/2 [mm²], длина оси L=hypot(dx,dy) [mm], объём V=B*L [mm³]. Это собственный геометрический вывод, не таблица ГОСТ. Приняты прямой угол, прямая грань и постоянные катеты вдоль участка. Нет усиления/вогнутости, провара, разделки, обрезки концов, поправок на пересечения, потерь, припусков, скорости/наплавки или стоимости. На стыках/пересечениях объёмы отдельных идеализированных призм суммируются без пространственного объединения; такая сумма не объявляется фактическим объёмом металла.

Эффективная ширина a=k1*k2/hypot(k1,k2) и эффективная площадь номинального расчёта a*L имеют другой смысл. Пример 3–4–5, L=100 mm: B=6 mm², V=600 mm³, эффективная площадь=240 mm². При удвоении обоих катетов объём возрастает в четыре раза, а эффективная площадь при прежней оси — в два. Поле с одной вручную заданной эффективной шириной не определяет катеты или объём: строка остаётся null.

Масса m=V*10^-9*rho [kg] использует исключительно применимую пользовательскую плотность наплавленного металла в kg/m³ из `Project.materials.weld`. Прежний resolver проверяет явный контекст `(t_min,t_max]` и `[T_min,T_max]`; плотность основного металла не подставляется. Нет карточки/свойства или контекст вне диапазона — масса неизвестна. Пример: 600 mm³ и 8000 kg/m³ → 0.0048 kg. Плотность не входит в номинальную механику, прочность или автоматически создаваемую инерционную нагрузку.

Ответ содержит per-segment длину/площадь/объём/массу, число известных участков, сумму известных объёмов и nullable полный объём/массу. Частичная известная сумма не выдаётся за полный объём. При отсутствии всех моделей known_volume=0 — только сумма пустого известного подмножества, полный volume/mass=null. complete относится к наличию всех геометрических сечений, не к плотности/прочности. Переполнение, нулевой/subnormal положительный промежуточный результат и потеря численного диапазона возвращают явную ошибку; промежуточные вычисления могут ограничить экстремальные масштабы даже при представимом конечном произведении.

Tauri `evaluate_quantities(request)`, REST `POST /api/v1/quantities/evaluate`; строгий QuantityRequest `{schema_version:1,segments,materials:null|MaterialSelection}` → QuantityResult с точным source echo. Старые правила валидности геометрии/согласованности катетов и a сохраняются. Используется общий Rust/application, frontend не вычисляет геометрию или массу. REST сохраняет прежние loopback/auth/workers/body/deadline ограничения.

Раздел «Объём и масса швов» в результатах получает данные при раскрытии; источник меняется — прежние данные немедленно становятся неактуальными, поздний ответ игнорируется. Модели/карточки сохраняются прежним JSON/SQLite, производные количества пересчитываются. Новых полей Project или миграции нет. PDF содержит формулы, исходный проект, численные/неизвестные строки и отдельный собственный `weld-quantities.json`; источник должен совпадать с текущими геометрией и материалами. Пороговые отношения и номинальные результаты остаются независимыми.
